# Передача работы — CSV структуры, быстрый анализ и остановка, 2026-09-12

## Последняя просьба
Пользователь сообщил о многочасовом переносе и потере соответствия исходным папкам. Потребовал CSV из нетронутого бэкапа с последующим сопоставлением плоского каталога, автосохранение CSV при переносе, Stop/продолжение, нумерацию, мультивыбор, постоянные колонки статистики, автоматический Unlock, удаление меню и подсчёта приложений.

## Реализовано
- «Бэкап: открыть без изменений» задаётся до открытия каталога. В этом режиме нет Unlock/изменений файлов/Word, состояние только во внешнем data root; CSV можно сохранить только вне исходного корня.
- Обычное открытие автоматически делает рекурсивный Unlock. Меню «Инструменты» удалено.
- №, Ctrl/Shift/Ctrl+A, сортировка всех колонок с индикатором направления. Стр./Рис./Табл. всегда видны, приложений нет.
- Итоги по всем документам без выбора или по выбранным. Знак > означает неполный охват, ≈ — сохранённые страницы. Только Word не гарантирует полноту DOC; неизвестные значения не приравниваются к нулю.
- Быстрый DOCX/XML и PDF; DOC страницы из SummaryInformation (olefile), без Word. Кнопка «Уточнить Word» для опционального полного пересчёта DOC/DOCX, не для бэкапа.
- manifest.py: переносимый CSV UTF-8 BOM с файлами, пустыми директориями, размером, SHA и исходными путями. Импорт сопоставляет по SHA+размеру, никогда не использует пути CSV для файловых действий.
- Одинаковый SHA в нескольких исходных папках: хранить/показывать все варианты origins, не выдумывать однозначное происхождение. По исходным путям работает поиск/выделение и действия по текущим путям.
- Автоматический <key>.structure.csv в LOCALAPPDATA/CorpusPick записывается до первого перемещения и после завершения/остановки. Ошибка первой записи блокирует перенос. Есть ручные «Сохранить CSV» и «Загрузить CSV».
- Stop/Esc через Event, отмена SHA по блокам; частичный анализ сохраняется, перенос продолжается с оставшихся файлов той же кнопкой после перезапуска.

## Производительность и происхождение
В прошлом полная JSON-сессия переписывалась для каждого файла, список просматривался линейно для каждого перемещения, хеширование повторялось при сканах. Теперь кэш по identity/size/mtime, dict для обновления пути, короткий append-only JSONL с fsync на шаг, полный checkpoint в начале/конце. Запись выполненного шага восстанавливается при старте; авария между rename и записью восстанавливается по идентификатору/хешу. Старые hard-link журналы поддержаны. Суффиксы коллизий используют счётчик вместо повторного поиска с 1.

## Ограничения и честность
Первое хеширование читает весь архив; скорость зависит от носителя. Stop ждёт текущий системный вызов при файловых операциях, Word — текущий документ до 120 с. Метрики DOC без Word неполные, DOCX pages могут устареть/отсутствовать. PDF рисунки/таблицы не считаются. Истинную прежнюю папку одной из идентичных копий нельзя установить только по SHA. Физическое восстановление дерева не добавлялось: импорт даёт виртуальную структуру и управление текущими файлами. Пользовательские архивы, CSV, базы/логи состояния и реальные документы не читались.

## Новая похожесть и фильтры колонок
Старый Dice + union-find заменён локальными TF-IDF слов/3–4-грамм (.65/.35), cosine и жадными группами с проверкой каждого уникального участника >=.62. Словарь строится по уникальным нормализованным именам; числа ×.25, служебные copy/final/копия/версия исключены из словесных признаков. Ограниченный инвертированный индекс вместо соседей: 24 редких признака с postings<=512, 64 кандидата. Не полная complete-linkage кластеризация; возможны пропуски, семантики/контента нет. Реализация stdlib, зависимости не добавлялись.
Меню заголовка ▾: направления сортировки, фильтр колонки, сброс одного/всех. filters.py: все/любое слово, целые слова или подстроки, исключения; числовые включительные границы. Несколько колонок соединены И; активные ●▾. Фильтр имени не смотрит origin. Отмена диалога не меняет правило. Новый каталог сбрасывает фильтры.

## Сходство содержимого
Добавлен content_similarity.py: raw SHA + Gear CDC 512–8192 байт, для <=32КиБ перекрывающиеся 16-byte shingles, bottom-k 256. Для DOCX/PDF/TXT/MD/CSV/TSV текст нормализуется в 5-word shingles, сохраняются только хеши/числа/статус. DOCX учитывает абзацы и headers/footers/notes, PDF весь извлекаемый текст без OCR, DOC только raw. Неполное извлечение не выдаёт готовый текстовый отпечаток. Byte Jaccard>=.85 / text>=.82 + длины>=.8, text>=10 слов, >=8 уникальных отпечатков для приблизительного сигнала. Изображения/вёрстка не сравниваются семантически.
Session.group_similar делает metadata scan, затем reuse StatsWorker с отдельным content_worker и таймаутом90/retry_label. Event убивает только свой процесс. Кэш content/version по identity, checkpoint5с/конец, повтор после ошибки. Успешный raw SHA передаётся обычному regroup; никакого fuzzy-delete. Content_order ищет по индексу отпечатков (списки максимум256), затем попарная совместимость внутри группы; TF-IDF названий fallback только если недостаточно текста у одной стороны. Основания в details, ошибки в фильтре; структура/CSV не меняются. Изменение набора/identity сбрасывает отображаемые группы.
Проверено 56 тестов: 53 прошли, 3 опциональные интеграции пропущены. Новые искусственные случаи: замена/вставка 1 байта при 4КиБ/32КиБ/150КиБ, разные байты той же длины, иной ZIP compression и небольшая текстовая правка DOCX, DOCX/TXT/PDF с разными именами, пустой PDF, повреждённый DOCX, cache/invalidation, stop/checkpoint/reopen, и near-match не попадает в duplicate_plan. Общие тесты StatsWorker проверяют принудительную отмену и таймаут собственного процесса. Не проверено на реальном архиве; данные пользователя не читались. Первое чтение тяжёлое, нет гарантии найти все близкие файлы, короткие/однообразные данные и сканы ограничены.

## Ускорение байтовых отпечатков
Устранён Python append/len/64-bit arithmetic для каждого байта. _chunk_end использует только низкие10бит Gear и последние10байт перед минимальной границей512; предыдущие502байта не влияют на условие rolling&1023. Блочная обработка с хвостом до8192 сохраняет прежние границы независимо от границ чтения1МиБ. VERSION остаётся1, кэш совместим.
Синтетический фиксированный random seed42, 16МиБ: прежний binary_fingerprint15,087с, новый5,254с (2,87x). Замеры в той же среде, реальный архив не читался; не обещать такой коэффициент всему проходу/извлечению текста. 57 тестов:54 прошли,3 опциональные интеграции пропущены. Новая эталонная проверка сравнивает chunk hashes с прежним побайтовым алгоритмом на пустом/однообразном/повторяющемся/random>1МиБ входе. Тесты однобайтовой правки/вставки, перехода32КиБ и stop/cache продолжают проходить.

## Группировка только по содержимому (2026-09-13)
Названия/пути и TF-IDF fallback исключены из content_order. Прежний жадный порядок по имени мог присоединить слабого кандидата раньше сильной пары. Теперь агломеративная complete-link на графе допустимых byte/text совпадений: heap сначала объединяет максимальное сходство, после merge остаются общие соседи с min(score). Точные SHA имеют приоритет. Идентичные отпечатки свёрнуты в единицы; порядок и разрешение равенства только по content-derived fingerprint_key. Неизвестные/ошибочные отпечатки всегда отдельно. Путь используется только как идентификатор строки, не признак. Подписи оснований обновлены, UI сообщает «только по содержимому».
Снято ограничение postings256; используются все кандидаты с общим отпечатком. Пороговые значения/формат отпечатков VERSION1 не менялись, прежний кэш совместим. Сравнение по отпечаткам фрагментов приблизительное, не прямой подсчёт одинаковых байтов. Complete-link намеренно не объединяет цепочки с несовместимыми крайними файлами. Плотные графы близких версий могут потребовать квадратичных времени/памяти; новых зависимостей нет.
Проверено 60 тестов:57 прошли,3 опциональные интеграции пропущены. Новые регрессии: независимость состава от имён/путей/входного порядка, неизвестные файлы с одинаковыми именами отдельно, strongest pair против раннего пограничного кандидата, совпадение за пределами256 кандидатов. Пользовательский архив/кэш не читались, качество на нём не измерялось.

## Порядок групп и одиночных файлов (2026-09-13)
Пользователь показал PDF около 56 КБ, между которыми после «По похожести» оказался XLSX 94 КБ. Причина: content_order присваивал каждому unmatched unit отдельную группу в порядке fingerprint_key; этот порядок нужен был для детерминированной кластеризации, но визуально выглядел случайным. Это не было ложным content-match с XLSX.
Теперь confirmed clusters (фактическое число документов >1, включая одинаковый fingerprint unit) идут первыми, по убыванию состава; внутри — suffix.casefold/size.
