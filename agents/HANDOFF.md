## Реализовано
- «Бэкап: открыть без изменений» задаётся до открытия каталога. В этом режиме нет Unlock/изменений файлов/Word, состояние только во внешнем data root; CSV можно сохранить только вне исходного корня.
- Обычное открытие автоматически делает рекурсивный Unlock. Меню «Инструменты» удалено.
- №, Ctrl/Shift/Ctrl+A, сортировка всех колонок с индикатором направления. Стр./Рис./Табл. всегда видны, приложений нет.
- Итоги по всем документам без выбора или по выбранным. Знак > означает неполный охват, ≈ — сохранённые страницы. Только Word не гарантирует полноту DOC; неизвестные значения не приравниваются к нулю.
- Быстрый DOCX/XML и PDF; DOC страницы из SummaryInformation (olefile), без Word. Кнопка «Уточнить Word» для опционального полного пересчёта DOC/DOCX, не для бэкапа.
- manifest.py: переносимый CSV UTF-8 BOM с файлами, пустыми директориями, размером, SHA и исходными путями. Импорт сопоставляет по SHA+размеру, никогда не использует пути CSV для файловых действий.
- Одинаковый SHA в нескольких исходных папках: хранить/показывать все варианты origins, не выдумывать однозначное происхождение. По исходным путям работает поиск/выделение и действия по текущим путям.
- Автоматический <key>.structure.csv в LOCALAPPDATA/CorpusPick записывается до первого перемещения и после завершения/остановки. Ошибка первой записи блокирует перенос. Есть ручные «Сохранить CSV» и «Загрузить CSV».
- Stop/Esc через Event, отмена SHA по блокам; частичный анализ сохраняется, перенос продолжается с оставшихся файлов той же кнопкой после перезапуска.

## Ограничения и честность
Первое хеширование читает весь архив; скорость зависит от носителя. Stop ждёт текущий системный вызов при файловых операциях, Word — текущий документ до 120 с. ## Сходство содержимого
Добавлен content_similarity.py: raw SHA + Gear CDC 512–8192 байт, для <=32КиБ перекрывающиеся 16-byte shingles, bottom-k 256. Для DOCX/PDF/TXT/MD/CSV/TSV текст нормализуется в 5-word shingles, сохраняются только хеши/числа/статус. DOCX учитывает абзацы и headers/footers/notes, PDF весь извлекаемый текст без OCR, DOC только raw. Неполное извлечение не выдаёт готовый текстовый отпечаток. Byte Jaccard>=.85 / text>=.82 + длины>=.8, text>=10 слов, >=8 уникальных отпечатков для приблизительного сигнала. Изображения/вёрстка не сравниваются семантически.
Session.group_similar делает metadata scan, затем reuse StatsWorker с отдельным content_worker и таймаутом90/retry_label. Event убивает только свой процесс. Кэш content/version по identity, checkpoint5с/конец, повтор после ошибки. Успешный raw SHA передаётся обычному regroup; никакого fuzzy-delete. Content_order ищет по индексу отпечатков (списки максимум256), затем попарная совместимость внутри группы; TF-IDF названий fallback только если недостаточно текста у одной стороны. Основания в details, ошибки в фильтре; структура/CSV не меняются. Изменение набора/identity сбрасывает отображаемые группы.

## Тематическая ML-кластеризация и карта (2026-09-13)

Это находит одинаковые/пересжатые сканы, но не определяет общую тему у разных изображений. pypdf заменён на pypdf[image]. TOPIC_VERSION2 заставляет старый cache выполнить только bounded pass первых12 PDF pages и визуальный pass для малотекстовых PDF; byte fingerprint заново не читается. text_failed PDF теперь тоже проходит этот worker.

После content/ML-групп только unmatched remainder проходит резерв: одинаковый suffix, fixed min/max size>=.5, TF-IDF слов65% + char3/4 35%, threshold.4. Для >4000 остаётся bounded inverted-index fallback. Accepted name groups явно подписаны как резервные и не могут изменить content/ML groups; одиночные затем идут в прежний 5% physical layout. На синтетических1000 сходных имён полный content_order после холодного импорта sklearn занял2,574с против7,561с у Python pair loop; это не замер пользовательских документов.

## Исследование следующего алгоритма (2026-09-14)
После обратной связи о дроблении общих классов («дипломы», «ноу-хау») исследованы актуальные локальные варианты. Текущий hashed TF-IDF+LSA теряет семантическое сходство, когда общая форма документа перекрыта уникальной предметной лексикой; HDBSCAN дополнительно может дробить неоднородные по плотности классы. Простая замена HDBSCAN без замены признаков проблему полностью не решит.

Рекомендуемый следующий эксперимент: multi-chunk document embeddings (обложка/начало+выборка середины+заключение) через Qwen3-Embedding-0.6B как quality-вариант и gte-multilingual-base как balanced-вариант; kNN cosine graph + Leiden для unsupervised групп, с optional agglomerative merge уровнем. Для image-only PDF — быстрый OCR sample pages через PP-OCRv5 перед тем же embedding pipeline; Qwen3-VL/ColQwen2 рассматривать только как тяжёлый GPU-режим. Если пользователь согласится дать локальные метки нескольким примерам повторяющихся классов, SetFit или linear SVM над embeddings должен быть точнее любой чистой кластеризации; неизвестные классы оставлять open-set по confidence/distance.

Модель и зависимости пока не добавлялись. Нужен локальный A/B benchmark: пары/группы размечаются пользователем в приложении, а наружу не выходят; сравниваются pairwise precision/recall/F1, число раздробленных эталонных классов, доля подмешиваний, время и peak RAM. Источники: Qwen3 Embedding arXiv2506.05176/model card; BGE-M3 arXiv2402.03216; gte-multilingual-base model card/arXiv2407.19669; MMTEB arXiv2502.13595; SetFit arXiv2209.11055; Leiden arXiv1810.08473; ColPali arXiv2407.01449; PaddleOCR3 arXiv2507.05595. ## Слабые метки и Linear SVM (2026-09-14)
По явной просьбе пользователя реализован первый supervised-эксперимент без новой модели. Если независимый класс только один, его seeds группируются напрямую без фиктивного SVM. В details показываются имя класса, источник и уверенность; UI summary считает SVM-классы. Модель/метки живут только в памяти, исходный текст не сохраняется и не передаётся.
Строгие SHA/byte/text/visual компоненты не изменены и объединяются с тематическими классами как раньше; автоматическое удаление по-прежнему только по SHA-256. Тест на17 синтетических документов подтверждает классы «акт», «дс», `other_1`, исключение пересечения из seeds и последующую классификацию спорного документа по содержанию. Отдельно проверена единая дефисная метка «ноу-хау». Все69 тестов прошли,4 опциональные интеграции пропущены. ## Preview cache stability (2026-09-15)
После сообщения пользователя, что пререндеренный preview не подхватывается при новом открытии программы, проверен путь disk-cache. Такой ключ быстрый, но может промахиваться после переименования/переноса, при виртуальном сопоставлении бэкап→плоский каталог или при нестабильном inode на Windows/cloud/network storage.

Полностью восстановить старый cache, если единственный legacy key стал недостижим из-за изменившегося inode/path, нельзя; после одного нового render/prerender эта версия пишет переносимый ключ и следующие открытия должны подхватывать PNG.

README обновлён: preview-cache больше не описан как только path+file identity. Добавлены synthetic tests: cached preview survives rename; legacy preview cache is read and migrated.
