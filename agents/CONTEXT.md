# Контекст и назначение
Пользователь готовит большой конфиденциальный архив как RAW DATA для последующей обработки.
Приоритет уточнён: отбор для RAG, затем возможные корпуса для дообучения (включая LoRA) и NER.
Наличие файла в RAW DATA не означает готовность к обучению. Для NER нужна схема сущностей и разметка.

## Текущая боль
- Множество вложенных каталогов; названия не отражают содержимое.
- В папках отчётов встречаются письма.
- Разные названия, размеры и форматы у копий и версий.
- DOCX/PDF могут представлять один документ; предпочтителен полный DOCX.
- Пользователь листает документы в Windows Explorer с Preview; это медленно.
- Решение о включении принимает человек.
- Пустые шаблоны, большая часть Excel и повторы обычно не нужны, но полезность не определяется расширением.

## Локальные каталоги
Реальные пути архива пользователь выбирает только в локальном интерфейсе.
Не включать личные пути в публичный репозиторий. Не сканировать архив для разработки.
Проект: C:\Dev\CorpusPick; подробные инструкции пользователь просит хранить в agents/.

## Ожидаемый процесс (актуальное уточнение 2026-09-12)
Просмотр и сортировка — Explorer/Preview. CorpusPick: структура папок/CSV, быстрый состав, точные дубли, перенос и корзина.
Критичный сценарий: открыть бэкап без изменений → сохранить CSV вне бэкапа → открыть плоскую копию → импортировать CSV по SHA-256.
Обычное открытие делает Unlock автоматически; в режиме бэкапа любые изменения файлов запрещены, включая Unlock.
При переносе CSV пишется до первого изменения и после завершения/остановки. Stop и продолжение после перезапуска обязательны.
Множественный выбор задаёт область итогов/статистики и удаления выбранных; сам перенос относится ко всему каталогу.
Исходные пути сохраняются в сессии/CSV; одинаковые хеши нескольких оригиналов отражаются как неоднозначные варианты.
Встроенный preview справа добавлен по просьбе 2026-09-14: PDF/изображения первая страница/кадр, текстовые форматы начало файла, DOCX/PPTX/XLSX через LibreOffice при наличии или быстрый OOXML-текст/таблица fallback. Меню Инструменты/подсчёта приложений нет. Метки «Скорее да» и их горячие клавиши удалены по просьбе 2026-09-13.
Уточнение: колонки «Примечание» нет; подсчёт только по кнопке «Статистика», при открытии — список и кэш. Обычные парсеры изолированы в отдельном процессе с отменой и лимитом 30 с на файл.

## Принципы отбора
- Точная копия: предложить один экземпляр.
- DOCX/PDF: предпочесть DOCX только при достаточной полноте и сопоставлении текста/приложений.
- Схожие отчёты разных периодов не считать автоматически дублями.
- Для RAG изменения решений и исторические версии могут быть полезны; сохранить период/версию.
- Уникальный скан с полезным текстом можно взять под OCR без ожидания распознавания.
- Отсутствие распознанного текста не означает отсутствие пользы.
- Файлы с новым содержанием в рамках темы важнее количества страниц или размера.
- Не исключать короткие письма, таблицы и формы только по их длине/типу.

Уточнение 2026-09-15: массовые «Добавить префикс»/«Убрать префикс» обновляют активные группы автоматически. F5 сохраняет отображаемые группы и обновляет признаки, цвета после clustering сопоставляются по overlap. Раздельный content cache позволяет обновлять названия без OCR; legacy mixed cache используется как фиксированная приблизительная основа, не требует общего повторного OCR. Изменение байтов инвалидирует только изменённый файл. Префикс — мягкий сигнал, не гарантированное ручное объединение.

Актуальный эксперимент от 2026-09-14: «По похожести» использует E5 названия/пути и bounded content. PDF: first/middle/last 120DPI, native text при >=20слов иначе локальный RapidOCR Cyrillic PP-OCRv5; DOCX/TXT/MD/CSV/TSV: head/sparse-middle/tail. Natasha/Slovnet заменяет PER/ORG/LOC, правила — даты/числа. Для PDF также строится384-d layout из text-box occupancy, projections и coarse ink; pairwise similarity может быть усилена общим layout, но не определяется им одним. Windows использует onnxruntime-directml: OCR автоматически GPU при DML/CUDA provider с runtime fallback на CPU; E5 INT8 остаётся CPU после локального A/B, где DML был медленнее. Кластеры average-link по precomputed distance, не k-NN; ползунок 20..50 меняет distance threshold, 35 default, после первого pass live regroup использует только cached vectors без scan/OCR/E5. Прежние SVM/HDBSCAN/content/size fallback не вызываются текущей кнопкой. OCR text/images/entity values не сохраняются, из worker возвращаются только numeric vectors/counts/status. Агент не читал пользовательский архив, имена или кэш. SHA-дубли работают отдельно.
