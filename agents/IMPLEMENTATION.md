# План реализации (предложение, пока не реализовано)
## Основа
TagSpaces отклонён пользователем и удалён. Новая основа ещё не выбрана.
Требуется компактный инструмент отбора без зависимости ключевых функций от платных модулей.
Варианты: минимальная собственная оболочка или более подходящая открытая основа.
Не возобновлять адаптацию TagSpaces без новой просьбы пользователя.

## Этап 1: полезный ручной отбор
- Виртуальный рекурсивный список с исходными путями, сортировкой и фильтрами.
- Статусы: непроверен, отчёт, письмо, взять под OCR, пропустить, позже.
- Клавиши действий + переход к следующему, отмена, сохранение прогресса.
- Постоянная короткая памятка рядом с предпросмотром.
- Отдельный каталог состояния вне исходников и исходного архива.
- Экспорт выбранных копий по двум категориям с защитой коллизий.
Не блокировать выпуск этапа наличием LLM, эмбеддингов и полного OCR.

## Этап 2: сравнение и подсказки
Три отдельных сигнала:
1. SHA-256 байтов — точные копии.
2. Совпадение нормализованного извлечённого текста — кандидаты в эквивалентные представления.
3. Приблизительное сравнение текстовых фрагментов — похожие версии.
Нормализация не должна стирать значимые числа, даты, подписи и приложения.
Совпадение текста не доказывает равенство изображений/таблиц; объяснять ограничения.
Показывать основания: качество извлечения, тематическая релевантность, новизна относительно выбранного,
потенциальные сущности NER, повторяемость. Не выдавать необоснованный «балл ценности для LLM».

## Этап 3: OCR без блокировки просмотра
- Сначала показывать страницы; OCR не нужен для изображения скана.
- Определять качество/наличие текста по страницам (PDF может быть смешанным).
- Предварительное OCR нескольких страниц: явная отметка частичного охвата.
- Tesseract rus+eng / tessdata_fast — кандидат для CPU-прохода, а не доказанный лучший движок.
- Полный OCR после отбора или по отдельной команде, в фоновой очереди.
- Таймаут/ошибка/пустой результат = неизвестно, а не «пропустить».
- Частичный OCR не использовать для уверенного удаления дублей или вывода «уникальный».
- Хранить движок/версию, язык, охват страниц, состояние и происхождение текста.
- Плохое качество OCR и необходимость проверить человеком видны в интерфейсе.

## Производительность
- Быстрый первый экран, ограниченная очередь рендеринга и отмена устаревшей работы.
- Предзагрузка соседних документов и кэш первых страниц.
- Кэш по идентификатору содержимого + версии рендера; инвалидация изменённого файла.
- Полный документ и страницы доступны, не ограничивать просмотр обложкой.
- DOCX→HTML быстрее потенциально, но не гарантирует вёрстку; точный режим требует отдельной оценки.
- Рендер/OCR/хеширование не выполняются синхронно в UI.
- Измерять холодное/повторное открытие, p50/p95 и серии переключений, не обещать превосходство без замеров.

## Git и проверки
Корневой Git-репозиторий сохранён. Клоны TagSpaces удалены; структура будущего кода ещё не выбрана.
Не редактировать node_modules как постоянный патч; менять исходный пакет и фиксировать воспроизводимую сборку.
Проверить актуальные package.json, а не слепо копировать команды CLAUDE.md (часть команд устарела).
Тесты по риску: коллизии имён, прерывание экспорта, изменения источника, восстановление решений,
ложные дубли разных периодов, частичный OCR и сохранение оригиналов.
Исходные приватные документы не нужны для этих тестов.
