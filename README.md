# CorpusPick

Локальный помощник для подготовки каталога документов рядом с Windows Explorer. CorpusPick сохраняет происхождение файлов, убирает вложенность, находит точные дубли, показывает статистику и даёт быстрый preview выбранного файла справа.

## Запуск

Windows, Python 3.10+ с Tcl/Tk. Установите зависимости: `python -m pip install -r requirements.txt`. Затем откройте `Start-CorpusPick.cmd`: при первом запуске он автоматически подготовит локальный рендерер Office. Потребуется интернет для загрузки 356 МиБ и около 1,5 ГиБ места после распаковки. Повторные запуски не скачивают пакет. Если подготовка не удалась, приложение всё равно открывается с доступными форматами preview. Прямой `python -m corpuspick` пропускает подготовку рендерера.

## Восстановить структуру из бэкапа для уже плоского каталога

1. **До открытия бэкапа** включите галочку **«Бэкап: открыть без изменений»**. Нажмите **«Открыть каталог»** и выберите бэкап с исходными подпапками.
2. Нажмите **«Сохранить CSV»**, выберите файл **вне каталога документов**. Программа читает файлы для SHA-256 и сохраняет структуру, включая пустые папки. В режиме бэкапа Unlock, перенос, удаление и запуск Word запрещены; ни содержимое файлов, ни Zone.Identifier, ни структура каталогов программой не меняются. Состояние анализа записывается только во внешний пользовательский каталог.
3. Снимите галочку бэкапа и откройте рабочий плоский каталог. В обычном режиме Unlock автоматически снимает отметку «скачано из интернета» со вложенных файлов. Не включайте обычный режим для бэкапа, который должен оставаться нетронутым.
4. Нажмите **«Загрузить CSV»**. Файлы сопоставляются по SHA-256 и размеру, поэтому их текущие имена и вложенность могут отличаться.
5. Колонка **«Исходный путь / варианты»** покажет прежние папки. Ищите по их названию, выделяйте строки и считайте статистику или удаляйте выделенные файлы. Действия используют текущие пути файлов, а пути из CSV служат только данными о происхождении.

Если один SHA-256 встречается в нескольких исходных папках, однозначно восстановить происхождение конкретной побайтовой копии невозможно. Для неё показываются **все возможные исходные пути**. Программа не назначает папку случайным образом. Если SHA получить не удалось или содержимое изменилось относительно бэкапа, совпадение не заявляется.

CSV имеет заголовок, разделитель `;` и кодировку UTF-8 BOM. Поля: версия схемы, вид строки (файл/каталог), текущий относительный путь, исходный относительный путь, размер, SHA-256 и список возможных исходных путей. Это не произвольный CSV из стороннего инструмента. Метки формул экранируются при сохранении и восстанавливаются при загрузке. CSV содержит чувствительные имена/пути: не публикуйте его в Git.

## Перенос, остановка и сохранение

**«Перенести в корень»** работает со всем каталогом независимо от выделения и фильтра. Совпадающие имена получают суффиксы без перезаписи. Пустые папки можно удалить отдельно.

CSV структуры автоматически сохраняется **до первого перемещения** и обновляется после завершения/остановки: `%LOCALAPPDATA%\CorpusPick\<идентификатор>.structure.csv`. Точный путь выводится по завершении операции. Если запись CSV не удалась, перемещение не начинается. Для собственного расположения и переносимой копии используйте **«Сохранить CSV»**. Исходные папки остаются в CSV и сессии после физического выравнивания.

**«Стоп» / Esc** приостанавливает работу и сохраняет прогресс. Для продолжения переноса нажмите ту же кнопку **«Перенести в корень»**; для подсчёта — **«Статистика»**. Это поддерживается и после перезапуска.

Хеширование прерывается между блоками чтения; перенос — между файлами. Статистика прерывает текущий обработчик. Word/COM не запускается; точный подсчёт документов Writer выполняется через изолированный LibreOffice. Медленный системный вызов диска/облачного провайдера не прерывается принудительно. Закрытие занятого окна сначала запрашивает остановку.

## Интерфейс и выбор

- Слева от имени — номер файла. **Ctrl/Shift** выделяют несколько строк, **Ctrl+A** — все видимые, **Esc** снимает выделение, когда операция не выполняется.
- Колонки **Стр. / Рис. / Табл.** всегда видны. Приложения больше не считаются.
- **«Статистика»** предлагает быстрый подсчёт и точное уточнение DOC/DOCX/RTF через LibreOffice.
- Сортировка работает по каждому заголовку, повторное нажатие меняет направление; числа сортируются как числа.
- Без выделения итог внизу относится ко всему каталогу. При выделении — только к выбранным файлам. Для возврата к общему итогу снимите выделение. Фильтр сам по себе не меняет общий итог.
- **Enter / двойной щелчок / ПКМ → «Показать в Проводнике»** передаёт выделенные файлы в Explorer. Для каждой текущей папки открывается окно с её частью выделения; чтобы не перегружать Explorer, за один вызов ограничено число папок и файлов. Вызов Explorer выполняется в отдельном фоновом потоке, чтобы зависший Shell не блокировал окно CorpusPick. В Проводнике можно вырезать всю выделенную группу и вставить в нужный каталог; затем F5 обновляет CorpusPick. Контекстное меню также копирует названия и пути. Метки и клавиша 2 удалены.
- **Delete** отправляет выделенные файлы в системную корзину после подтверждения. **«Удалить дубликаты»** сохраняет один экземпляр группы: ближе к корню, затем по имени. При наличии выделения удаляются только выделенные лишние копии; сохраняемый экземпляр может находиться вне выбора. Содержимое обеих копий проверяется перед удалением.
- Меню «Инструменты» и отдельной кнопки Unlock нет. Unlock снимает только Zone.Identifier; права доступа, пароли и блокировку открытым редактором не снимает.

## Preview справа

Кнопка **«Скрыть preview» / «Показать preview»** включает правую панель. Между таблицей и preview есть зона перетаскивания шириной 4 px, внутри неё видна тёмная линия 2 px. Подпись preview находится под областью просмотра. Preview запускается только для одного выделенного файла; при быстром переключении старый запрос отменяется или его результат игнорируется.

- **PDF** рендерится как картинка первой страницы через PyMuPDF.
- **Изображения** показываются уменьшенной первой страницей/кадром.
- **TXT/MD/CSV/TSV/JSON/XML/HTML и другие текстовые форматы** показывают начало файла.
- **DOC/DOCX/RTF** используют существующий кэш или LibreOffice; для DOCX доступен текстовый fallback. Новый Word не запускается.
- **PPT/PPTX** используют существующий кэш или LibreOffice; для PPTX доступен текст первого слайда. Новый PowerPoint не запускается.
- **PPTX/XLSX и fallback для DOCX** пробуют визуальный рендер первой страницы/слайда/листа через установленный LibreOffice. Если его нет или он не успел, показывается быстрый содержательный preview из OOXML: текст DOCX, первый слайд PPTX или первые строки первого листа XLSX.
- **XLS** без LibreOffice не имеет надёжного быстрого preview.

Preview выполняется в тёплом отдельном процессе с таймаутом 25 секунд и не блокирует окно. В памяти окна держится короткий LRU-кэш для уже просмотренных файлов текущего запуска. Картинки первой страницы PDF/Office дополнительно кэшируются локально в `%LOCALAPPDATA%\CorpusPick\preview-cache`, чтобы повторный preview не запускал Word/PowerPoint/LibreOffice заново. Кэш проверяется сначала по быстрым признакам пути/размера/времени изменения, затем по короткому содержательному отпечатку начала и конца файла; поэтому уже посчитанный preview переживает перезапуск, переименование и часть сценариев с переносом в рабочую плоскую папку. Если картинка уже есть в этом кэше, окно читает её напрямую, без нового запроса в preview-worker. Worker-процессы preview периодически пересоздаются, чтобы сбрасывать нативное состояние библиотек после серии файлов. Извлечённый текст на диск не пишется; PNG preview считается чувствительным содержимым и хранится только в локальном data root.

На Windows обработчики принадлежат Job Object с KILL_ON_JOB_CLOSE: закрытие приложения, его авария или таймаут завершают принадлежащие ему процессы. Обработчик начинает работу только после успешного включения в job; при ошибке изоляции запуск отменяется. Сессия LibreOffice имеет собственный job и временный профиль и обслуживает несколько файлов подряд. Word/PowerPoint COM отключён, поскольку системный COM-брокер создавал процессы вне дерева приложения и COM менял общие настройки Office. Существующий кэш продолжает работать. Автозапуски и службы приложение не устанавливает.

**«Пререндер»** заранее строит preview-кэш: если есть выделение — для выделенных файлов, иначе для всех видимых строк с учётом фильтров. Он сначала обрабатывает Office-форматы отдельной последовательной очередью через один worker, чтобы не запускать несколько LibreOffice одновременно; PDF и изображения откладываются в последнюю очередь и строятся максимум двумя изолированными worker-процессами. Поэтому задачу можно остановить после долгих DOC/DOCX/RTF/PPT/PPTX/XLS/XLSX и не ждать оставшиеся PDF. Текстовые/неподдержанные форматы и служебные временные Office-файлы вида `~$...` сразу пропускаются, потому что для них нет полезного PNG-кэша; уже готовые картинки из disk-cache тоже только засчитываются. Если визуальный Office-render сработал, PNG первой страницы/слайда сохраняется в disk-cache, и следующий preview открывается напрямую из него. Если LibreOffice не стартует или несколько раз подряд зависают, renderer отключается в текущем preview-worker и используется быстрый fallback; ошибки открытия отдельных документов renderer не отключают. Office COM отключён без возможности включения переменной окружения. Ошибки отдельных файлов только считаются в итогах и не останавливают очередь; зависшие обработчики изолированы в worker-процессе с таймаутом 25 секунд. Worker-процесс пререндера также периодически пересоздаётся. Для больших видимых списков программа попросит подтверждение. Stop прерывает очередь между файлами.

## Статистика

При открытии и обновлении читается только список файлов и сохранённые результаты. Подсчёт страниц, рисунков и таблиц запускается кнопкой **«Статистика»**: по выбранным документам или всему каталогу, если ничего не выделено. Неизвестные значения обозначены `—`, а не нулём. Результаты появляются после завершения или остановки; во время работы показан счётчик обработанных файлов, имя и формат текущего файла.

| Формат | Страницы | Рисунки / таблицы |
| --- | --- | --- |
| PDF | Число страниц PDF, без запуска Word | Не считаются |
| DOCX | Быстро: сохранённое число страниц из свойств, знак `≈`; уточнение: по текущей разметке LibreOffice | Быстро: объекты и таблицы основного текста из XML; уточнение: объекты Writer |
| DOC | Быстро: сохранённое число страниц из OLE-свойств, знак `≈`; уточнение: по текущей разметке LibreOffice | Быстро неизвестны; уточнение: объекты Writer |
| RTF | В быстром режиме неизвестны; уточнение: по текущей разметке LibreOffice | Уточнение: объекты Writer |

В меню **«Статистика»** быстрый подсчёт работает для выбранных документов или всего каталога. Пункт **«Точный подсчёт DOC/DOCX/RTF через LibreOffice»** уточняет только эти форматы; PDF и остальные файлы пропускаются. LibreOffice получает временную копию, использует отдельный профиль и ограниченный worker-процесс; Word/COM не запускается. Ошибка одного документа не прерывает очередь, а при сбое сохраняются прежние быстрые значения. Время на один файл ограничено 45 секундами.

В итогах знак **`>`** используется по запросу пользователя как индикатор **неполного подсчёта**, а не строгое математическое неравенство: например, рисунки/таблицы посчитаны по Word, а в выборе есть PDF. Когда выбраны только Word и все значения известны, `>` не ставится. Для неполных данных DOC он остаётся и в выборке Word. `≈` для сохранённых страниц не снимается из-за выбора только Word. Рядом указано покрытие `известно/всего`.

## Производительность

Неизменившиеся файлы не хешируются повторно: кэш проверяется по идентификатору файла, размеру и времени изменения. При открытии SHA не вычисляется: он рассчитывается кнопкой «Найти дубли», при работе с CSV, удалении дублей и переносе. Первое вычисление SHA-256 всё равно требует прочитать все байты — для большого архива это может быть долго. Оно необходимо для сопоставления разных каталогов и точных дублей.

Быстрая статистика считается в отдельном процессе: медленный разбор PDF/DOCX не занимает процесс окна. Лимит — 30 секунд на документ, затем файл пропускается с ошибкой; повторный запуск статистики повторяет неудавшиеся попытки. Точный подсчёт Writer использует отдельную ограниченную сессию LibreOffice с таймаутом 45 секунд на документ. «Стоп» завершает текущий обработчик и сохраняет готовые результаты. Список больше не перестраивается каждую секунду.

При переносе больше нет полного хеширования до и после каждого прохода, полного переписывания состояния для каждого файла и линейного поиска файла в списке. Короткий журнал завершённых перемещений синхронизируется на диск после каждого шага; полная сессия сохраняется в начале/конце. Нумерация коллизий также не перебирает заново все прошлые суффиксы.

На искусственном наборе из 500 маленьких файлов с одинаковыми именами в разных папках: первичный обход/хеширование 3,61 с, перенос с кэшем и CSV 2,70 с в среде разработки. Это не оценка скорости реального архива или сетевого диска. Оставьте документы закрытыми во время переноса, работайте с копией архива.

## Состояние и проверки

Состояние, короткий журнал и автоматический CSV находятся в `%LOCALAPPDATA%\CorpusPick`, вне исходного каталога и Git. Исходные документы/кэши пользователя агентом не читаются. Кроме явно подтверждённой однократной загрузки моделей, Python-часть не отправляет сетевых запросов и не логирует извлечённый текст. Уже завершённые переносы автоматически не отменяются.

Диагностический журнал ошибок пишется в `%LOCALAPPDATA%\CorpusPick\logs\corpuspick.log` с ротацией. В нём сохраняются traceback-и, имя операции и тип сбоя; содержимое документов не пишется, абсолютные пути в сообщениях заменяются на `<path>`.

`python -m unittest discover -s tests -v`

Опционально `CORPUSPICK_TEST_RECYCLE=1` — проверку корзины на искусственном файле с восстановлением. Все тесты используют только синтетические документы.

Правой кнопкой по строке → **«Показать в Проводнике»** открывает текущие папки и выделяет все выбранные файлы, в том числе после загрузки CSV исходной структуры. **«Скопировать название»** копирует имя с расширением; для нескольких выделенных файлов — по одному на строку.

## Выбор, очистка префиксов и похожие названия

Номера записываются в имена с ведущими нулями: `#01`…`#99`. При добавлении сотого участника все файлы этой серии в открытом каталоге и подпапках переименовываются в `#001`…`#100`, включая невыделенные; при тысячном ширина увеличивается до четырёх цифр. Уже установленная ширина не уменьшается. Расширения, содержимое и кэш сохраняются; при конфликтах файлы не перезаписываются.

**ПКМ → «Переименовать…»**: для одного файла вводится новое имя без расширения. Для нескольких — общее название; программа добавляет ` №1`, ` №2`, … в порядке строк таблицы, сохраняя расширение каждого файла. Например: `НОУ-ХАУ №1.pdf`, `НОУ-ХАУ №2.docx`. Занятые имена пропускаются без перезаписи. После операции активные группы обновляются с использованием кэша содержания.

Для нумерации выбираются наименьшие свободные номера от `#1`, включая пропуски. Проверяются текущие имена во всём открытом каталоге и подпапках, независимо от расширения и регистра; старый знак `№` также распознаётся. При замене `№` на `#` у выбранной пачки её старые номера освобождаются. Уже существующие целевые имена других файлов сохраняются; повторное переименование готовой серии не сдвигает её за последний номер. Последний номер не кэшируется. Колонка «Файл» использует естественную сортировку: `#1`, `#2`, `#10`.

Ctrl+A выделяет все видимые строки и работает в русской/английской раскладке, в том числе после нажатия кнопки. В поле поиска сочетание выделяет текст. Ctrl/Shift позволяют выбрать несколько файлов.

**«Убрать префикс»** открывает поле «Сколько символов убрать?». Введите положительное целое число и нажмите ОК: у выбранных файлов удалится указанное количество символов слева. Отмена закрывает окно без изменений. Расширение сохраняется; пустые/недопустимые имена и конфликты пропускаются без перезаписи. Исходные пути и статистика сохраняются. Операция использует журнал переноса и автоматический CSV; после Stop оставшиеся шаги можно выполнить кнопкой **«Перенести в корень»**. В режиме бэкапа переименование запрещено.

**«Добавить префикс»** открывает окно с текстом и опцией добавления названий 1–3 текущих родительских каталогов. Верхняя граница — открытый каталог включительно; родители идут от внешнего к внутреннему. Можно добавить в начало имени либо в конец перед расширением. Пробелы и слэши в добавляемой части заменяются на `_`. Предпросмотр первых трёх выбранных файлов обновляется при изменении настроек. Конфликты пропускаются, исходные пути сохраняются. Общий текстовый префикс влияет на сходство, но не гарантирует одну группу: содержание и макет также учитываются. Цифровые префиксы исключены из признаков.

При активной группировке F5 обновляет список и группы; добавление/удаление префикса запускает обновление групп автоматически. До окончания сохраняются прежние группы, после пересчёта цвета сопоставляются по общим участникам. При переименовании неизменившегося файла используются сохранённые content/layout-векторы: пересчитываются только E5 и лексика метаданных. Внешнее переименование распознаётся по уникальному идентификатору файла, размеру и времени изменения. Если менялись байты, извлечение/OCR повторяется только для изменённых файлов. Старые кэши, в которых нет отдельного content-вектора, используют прежний смешанный вектор как фиксированную основу без повторного OCR; в этой основе остаётся влияние прежних названий. Новые записи сразу сохраняют раздельные части.

**«По похожести»** строит локальные embeddings названия, исходного пути и ограниченной выборки содержимого. Для PDF берётся только первая страница при 120 DPI: её текст и макет. Если на странице уже есть не менее 20 слов текстового слоя, используется он; иначе запускается Cyrillic PP-OCRv5 mobile через ONNX. Для DOCX/TXT/MD/CSV/TSV берутся начало, разреженная выборка середины и конец. Другие форматы получают только metadata-embedding. Полный OCR документа не выполняется. После перехода на одностраничный режим старые признаки один раз пересчитываются автоматически.

Перед embedding применяется Unicode NFKC + lowercase/casefold. В названиях и путях ФИО заменяются маркерами, а цифры и даты исключаются полностью, без маркеров «номер»/«дата» в признаках. Для извлечённого/OCR-текста компактная Natasha/Slovnet NER на CPU распознаёт PER/ORG/LOC, а локальные правила — даты и числа; значения заменяются маркерами `персона`, `организация`, `место`, `дата`, `число`. Это уменьшает дробление одинаковых форм из-за конкретных реквизитов. NER обучен преимущественно на новостных текстах, поэтому в деловых документах возможны пропуски.

При первом запуске CorpusPick предлагает скачать закреплённые модели: INT8 `multilingual-e5-small` около 135 МБ и Cyrillic PP-OCRv5 recognition около 8 МБ. Они проверяются по размеру и SHA-256, хранятся в `%LOCALAPPDATA%\CorpusPick\models` и работают локально офлайн. Детектор текста и поворота входят в пакет RapidOCR. E5 дополняется локальным разреженным embedding слов и биграмм обезличенных метаданных.

На Windows используется `onnxruntime-directml`. Если доступен DirectML или CUDA provider, RapidOCR автоматически использует GPU; при ошибке той же страницы выполняется fallback на CPU. E5 INT8 намеренно остаётся на CPU: на тестовой RTX 2060 короткий batch E5 занял около 134 мс через DirectML против 27 мс на CPU, тогда как OCR искусственной русской страницы ускорился примерно с 2171 до 450 мс. Это локальный ориентир после прогрева, а не гарантия для любого GPU или PDF. В основании строки и статусе видно, применялся ли GPU OCR.

Для каждой выбранной PDF-страницы строится отдельный layout-вектор: сетка расположения текстовых блоков, вертикальные/горизонтальные проекции и грубая карта чернил. При попарном сравнении основной сигнал — 60% E5 и 40% точная лексика названия/пути. Внутри E5 при наличии текста веса равны 60% для выборки содержания, 23% для названия, 12% для каталогов и 5% для типов сущностей. Поэтому в обычном базовом сравнении ориентировочный вклад содержания — 36%, а названия, пути и типов сущностей вместе — 64%; это веса признаков, не вероятность правильности. Если layout есть у обоих документов, очень похожая структура может дополнительно сблизить отчёты с разным текстом по ветке 55% основного сигнала + 45% layout.

Группы строятся не k-NN, а иерархической average-link кластеризацией по cosine-дистанции, без заранее заданного числа классов. Ползунок **«Группы»** управляет порогом: 20 даёт более строгие и мелкие группы, 50 — более мягкие и крупные, 35 — исходный баланс. После первого расчёта изменение ползунка перестраивает только группы из кэшированных векторов и не повторяет OCR либо E5. В кэш записываются только float16-векторы, количества сущностей, число обработанных страниц и статусы. Извлечённый и OCR-текст, изображения страниц и значения сущностей не сохраняются и не выходят из изолированного worker.

**Сброс кэша:** ПКМ по кнопке «По похожести» / «Снять группировку» → «Сбросить кэш похожести». После подтверждения удаляются только отпечатки похожести текущего каталога; исходные пути, журнал переносов, CSV, SHA точных дублей и статистика остаются. Затем можно повторить сравнение. Состояние хранится в `%LOCALAPPDATA%\CorpusPick`; не удаляйте всю папку ради пересчёта похожести — там также сохранена исходная структура. Сброс разрешён и в режиме бэкапа, поскольку записывает только внешнее состояние программы.

Старые функции строгих байтовых/текстовых отпечатков остаются в коде и тестах, но текущая кнопка не смешивает их с ML-группами и не использует размерные псевдогруппы. «Найти дубли» по SHA-256 работает отдельно.

**Похожие файлы автоматически не удаляются.** «Удалить дубликаты» по-прежнему работает только с точным SHA-256 и повторной проверкой перед корзиной. Отбор похожих версий — вручную через выделение и Проводник.

После **«По похожести»** пункты сортировки в меню заголовка ▾ сортируют внутри каждой группы, сохраняя порядок групп. В меню можно выбрать направление сортировки. **«Снять группировку»** возвращает обычный список и сортировку по всему каталогу. При открытии другого каталога группировка сбрасывается.

После группировки текст каждой строки окрашен цветом её группы. Цвет сохраняется при дополнительной сортировке колонок внутри групп; одинаковый цвет означает один блок текущего результата. Для точного основания выделите строку: под таблицей будут указаны средняя близость, число sampled/OCR-страниц, наличие layout и распознанные типы сущностей.

## Фильтры колонок

Нажмите заголовок **«Файл ▾» → «Фильтр…»**. Введите слова, например `насос испытания`: по умолчанию должны встретиться все части слов, в любом порядке. Галочка **«Слова целиком»** позволяет отличить `акт` от `контракт`. Есть режим любого слова и поле исключений. Фильтр названия проверяет только имя файла, а не исходную папку из CSV. Общая строка поиска продолжает искать и по путям.

Такое же меню есть у каждой колонки: для типа/папок — текстовый фильтр, для байт/страниц/рисунков/таблиц — включительные границы «От» и «До». Неизвестные значения не проходят числовой фильтр. Фильтры колонок соединяются условием И, сочетаются с группировкой и сортировкой. Активный фильтр отмечен **●▾**. **Ctrl+A** выделяет все видимые результаты; их можно передать Проводнику. Пустые поля снимают фильтр колонки; в меню есть снятие одного или всех фильтров. Новый каталог сбрасывает фильтры колонок.

**«Найти дубли»** отдельно проверяет SHA-256 всех файлов выбранного каталога, включая подпапки, без удаления и подсчёта страниц. В колонке «Дубль»: **«Не проверен»** — SHA ещё не вычислен (раньше показывался `?`); **#номер** — группа точных копий; **—** — среди проверенных файлов совпадений нет. Пока проверка неполная, отсутствие группы не доказывает уникальность во всём каталоге. После остановки повторная кнопка продолжает проверку, используя кэш. При первом запуске читаются все байты файлов, поэтому большой архив требует времени.

Оптимизация байтового анализа: rolling hash вычисляется только там, где возможна граница блока, без добавления каждого байта в Python-буфер. Отпечатки совместимы с прежним кэшем. На искусственном файле 16 МиБ расчёт байтовых отпечатков ускорился с 15,09 до 5,25 с (примерно 2,9 раза); это не оценка времени извлечения PDF/Word-текста или всего реального архива. Для применения обновления к текущей обработке нажмите «Стоп», дождитесь сохранения, перезапустите приложение и снова запустите «По похожести».

## Визуальный preview Office без Word

Для DOC/DOCX/RTF, PPT/PPTX и XLS/XLSX используется отдельная локальная копия LibreOffice. На этой машине она уже подготовлена в `apps/LibreOffice`. На новой машине достаточно открыть `Start-CorpusPick.cmd`; для отдельной подготовки можно выполнить `powershell -NoProfile -ExecutionPolicy Bypass -File .\Setup-Preview.ps1`. Скрипт скачивает официальный пакет 26.2.6, проверяет SHA-256/подпись и извлекает его без регистрации файловых ассоциаций, автозапуска и служб. Для применения перезапустите CorpusPick.

Рендерер получает временную копию каждого документа; отдельный временный профиль принадлежит его рабочей сессии. Макросы, активные OLE/DDE-объекты, обновление ссылок Writer/Calc и автоматическая проверка обновлений выключены; ссылки из недоверенных документов блокируются настройкой LibreOffice. Это ограничения рендерера, а не полноценная ОС-песочница для произвольного вредоносного файла. Внешние картинки/связанные данные могут отсутствовать в preview.

Экспортируется только первая страница/слайд. На Windows для сессии рендерера выделяется Job Object с лимитом памяти 1,5 ГиБ; лимит конвертации 20 секунд, внешнего preview-worker 25 секунд. Stop завершает worker без ожидания этих сроков. Документ закрывается после каждой конвертации. Процессы сессии завершаются при закрытии/перезапуске обработчика, ошибке конвертации, таймауте и аварии владельца. Конвертер может разбирать весь исходный документ даже при экспорте одной страницы. COM Office остаётся отключённым.

Первое использование ожидает готовности фонового рендерера; следующие файлы используют ту же сессию, а повторный просмотр документа — PNG-кэш. «Пререндер» готовит изображения заранее. Вёрстка и переносы строк могут отличаться от Microsoft Office. Если конвертация недоступна, для OOXML остаётся текст/таблица; для старых бинарных DOC/PPT/XLS точного встроенного fallback нет.


### Как зафиксированы зависимости

- `requirements.txt` — Python-пакеты.
- `runtime-dependencies.json` — внешний рендерер LibreOffice: версия, платформа, официальные URL, SHA-256, назначение и лицензия.
- `Setup-Preview.ps1` и `Start-CorpusPick.cmd` — автоматическая подготовка и запуск.
- `apps/` и `downloads/` исключены из Git: бинарный офисный пакет не раздувает репозиторий. При переносе готовой папки приложения вместе с `apps/LibreOffice` повторная загрузка не требуется.

LibreOffice не обязателен для PDF/изображений/текста и основных операций CorpusPick. Он требуется для новых визуальных Office-preview. В текущей локальной поставке: 356 МиБ установочный пакет и 1526 МиБ извлечённые файлы; headless означает запуск без интерфейса, а не маленький дистрибутив. Официальная Portable-версия также является полным офисным пакетом. Непроверенное удаление библиотек ради уменьшения размера не применяется.

### Готовый рендерер и повторное использование

При запуске окна фоновый preview-worker заранее запускает LibreOffice. Подготовка занимает время, но не блокирует интерфейс. После готовности новые DOC/DOCX и другие Office-файлы обрабатывает тот же процесс через локальный UNO pipe, без запуска Office на каждый клик. TCP-порт не открывается. Для каждого открытия явно заданы ReadOnly, Hidden, NEVER_EXECUTE, NO_UPDATE и запрет добавления в недавние документы; документ закрывается до следующего запроса.

Пререндер использует свою последовательную Office-сессию для разных форматов. Интерактивный preview и пререндер могут иметь по одному рендереру, чтобы не блокировать друг друга. Весь worker вместе с LibreOffice обновляется после 40 обработанных запросов; при ошибке/таймауте испорченная сессия закрывается и создаётся заново для следующего файла. PDF/изображения остаются отдельной ограниченной очередью. PNG-кэш пропускает повторную конвертацию полностью.

На искусственном DOCX: подготовка сессии ~9,6 с, первый документ ~0,9–1,2 с, следующие ~0,19–0,25 с; в предыдущем варианте новый запуск занимал ~10–12 с на файл. Это локальный замер на маленьком документе, не гарантия скорости для произвольного архива.

### Ресурсы preview после пререндера
LibreOffice запускается при первом промахе кэша и переиспользуется для следующих новых Office-файлов. При переходе на готовый кэш, завершении пререндера или 15 секундах простоя интерактивный renderer освобождается; следующее некэшированное Office-preview потребует холодного запуска. Пререндер переиспользует свой renderer и закрывает его после работы. В RAM хранится не более 32 МиБ полезных данных кэша, без ограничения количества картинок (декодированная текущая картинка и библиотеки учитываются отдельно). Готовые PNG на диске автоматически не вытесняются: большой пререндер больше не удаляет собственное начало. Поэтому дисковый кэш растёт с числом документов; это сохраняемые результаты, а не занятая RAM.

Справа внизу показан размер дискового кэша preview (фоновое обновление каждые 10 секунд). Кнопка 🗑 очищает его после подтверждения, когда нет активной операции. Исходные документы не удаляются; следующий preview создаётся заново.

Пререндер пропускает готовый кэш. При достижении 2 ГиБ на диске он запрашивает решение, показывая оставшиеся некэшированные файлы по форматам: «Продолжить» разрешает весь текущий запуск, «Достаточно» останавливает его с сохранением результатов. Это не лимит вытеснения: PDF не удаляют Office-preview. Порог проверяется между файлами; уже выполняющийся параллельный файл может завершиться.

Start-CorpusPick.cmd запускает окно независимо от консоли через corpuspick.launcher. Наблюдатель записывает только время, PID и код завершения в локальный logs/process-exits.jsonl; содержимое документов и сообщения парсеров туда не попадают. Прямой python -m corpuspick обходит наблюдатель.

Меню 🔧 справа от «Удалить дубликаты» → «Сократить длинные названия…» сокращает длинные пути во всём открытом каталоге до совместимого предела259 единиц UTF-16, с ограничением255 на компонент. Переименовываются необходимые документы/вложенные папки, расширения сохраняются, коллизии не перезаписываются. Корневая папка не меняется; слишком глубокое дерево или длинный путь самого корня может потребовать выбора более короткого расположения. Перед изменениями сохраняется CSV исходных путей, переименование папок защищено журналом восстановления. В режиме бэкапа действие недоступно.
